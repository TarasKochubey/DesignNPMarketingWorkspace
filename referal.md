Business value: Керувати сумою винагороди за участь у реферальній програмі для окремої групи користувачів.
BR-SP_REW Бізнес-правила

BR-SP_REW-01. У маркетинговій адмінці має існувати окремий розділ “Реферальна програма” для керування спеціальною винагородою реферальної програми.
BR-SP_REW-02. Сума для дебетної картки застосовується для дебетного сценарію реферальної програми.
BR-SP_REW-03. Сума для кредитної картки застосовується для кредитного сценарію реферальної програми.
BR-SP_REW-04. Сума спеціальної винагороди застосовується до всіх користувачів, доданих до переліку у розділі “Реферальна програма”.
BR-SP_REW-05. Для реферера і реферала застосовується однакова сума спеціальної винагороди.
BR-SP_REW-06. Спеціальна винагорода має пріоритет над іншими типами винагороди.
BR-SP_REW-07. Система зберігає історію ввімкнення, вимкнення, зміни суми, додавання користувача та видалення користувача.
BR-SP_REW-08. Якщо на момент фактичного нарахування спеціальна винагорода активована і користувач є в переліку, застосовується актуальна спеціальна сума з адмінки.
BR-SP_REW-09. Якщо на момент фактичного нарахування спеціальна винагорода вимкнена або користувача немає в переліку, застосовуються стандартні правила винагороди.
US-REW-03 Спеціальна винагорода

technologist
Як авторизований користувач маркетингової адмінки
Я хочу активувати спеціальну винагороду, встановити її розмір і управляти переліком користувачів для кого задіяти винагороду,
щоб заохочувати певних клієнтів для розповсюдження реферального посилання із “приємнішою“ сумою.
Критерії приймання

Користувачу адмінки доступний розділ “Реферальна програма” в адмінці Лояльності.
Сторінка відображає перемикач (тогл) “Активувати” для керування спеціальною винагородою:
Користувач адмінки може увімкнути / вимкнути спеціальну винагороду зміною тогла.
Встановлення суми

Система дозволяє активувати спеціальну винагороду тільки якщо поля суми винагороди заповнені валідним значенням.
Сторінка відображає окремі поле для введення суми винагороди:
Сума для дебетної картки [Reward_Debit];
Сума для кредитної картки [Reward_Credit].
Значення для кожного поля суми має бути валідоване для збереження:
Поле приймає тільки цілі числові значення;
Поле приймає тільки цифри від 0 до 9;
Поле НЕ приймає літери, пробіли, спеціальні символи, + та -, десяткові роздільники . та ,, значення з копійками;
Значення в полі відображається без пробілів і роздільників тисяч;
Значення має бути більше 0.
При помилці валідації відобразити помилку поля “Невірний формат“;
Кнопка “Зберегти” для суми доступна тільки якщо введене значення не дорівнює поточному значенню цього ж поля;
Зміна суми зберігається в історії змін із зазначенням “попередня сума → нова сума”.
Після збереження нова сума застосовується:
для відображення у мобільному застосунку потенційної винагороди реферера і його реферала;
до майбутніх фактичних нарахувань, які ще не були виконані.
Додавання клієнтів у перелік

Сторінка відображає окреме поле для пошуку і додавання користувача.
Користувач адмінки може знайти клієнта NovaPay за основним номером телефону.
Note: пошук можна виконувати після вводу 3-х символів (для оптимізації пошуку)
Результат пошуку відображається у випадаючому списку, виводити перші 5 співпадінь, візуально підсвічувати співпадіння.
Співпадіння цифр пошукового поля і номеру телефону мають бути тільки поспіль.
Результат пошуку відображається у форматі “Номер телефону (Прізвище)“, напр., +380500113268 (Шевченко)
Користувач адмінки може додати клієнта після вибору результату з випадаючого списку і подальшого збереження вибору.
Система додає до переліку тільки користувача з NovaPay-профілем (обрати можна тільки з випадного списку).
Доступне додавання тільки по одному клієнту.
Перелік клієнтів зі спеціальною винагородою

Після збереження система відображає доданого користувача у списку “Додані користувачі”.
Система відображає загальну кількість доданих користувачів у заголовку списку.
Система відображає для доданого користувача номер телефону та прізвище.
Система не створює дубль для користувача, який вже є у переліку.
На переліку доступний скрол при перевищенні переліком меж екрану.
Видалення клієнтів з переліку спецвинагороди

Користувач адмінки може ініціювати видалення користувача зі списку – система показує модалку підтвердження перед видаленням користувача.
Після підтвердження система видаляє користувача зі списку;
Після відмови модальне вікно закривається без змін у списку.
Система зберігає видалення користувача в історії змін.
Історія змін

Сторінка відображає блок “Історія змін” з наступними колонками:
дата і час події;
логін користувача адмінки, який виконав дію;
тип події;
номер телефону для події додавання / видалення користувача;
“попередня сума → нова сума” для події зміни суми дебетної / кредитної картки;
для інших подій – пусте поле / нуль / прочерк.
Можливі типи подій:
додано користувача;
видалено користувача;
змінено суму дебетної картки;
змінено суму кредитної картки;
активовано спеціальну винагороду;
деактивовано спеціальну винагороду.
Історія змін підтримує підвантаження попередніх записів / скрол, якщо перелік подій перевищує межі екрану.
